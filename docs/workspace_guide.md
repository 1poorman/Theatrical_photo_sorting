# 幕间 · 多模态戏剧影像整理工作台

入口：启动 `python app/server_ui.py`，访问 `http://localhost:8199/organize`。`/ui` 同样打开工作台，`/` 重定向到工作台。

之前的可视化界面完整保留：工作台右上角「旧版界面」（桌面及手机均可见）或 `/legacy` 打开旧版照片处理页 `/legacy/ui`；原有智能整理表单位于 `/legacy/organize`。两页可通过顶部导航切换，也可点击「返回新版工作台」。原工具入口 `/tools` 和 `/organize/advanced` 继续可用，分别对应上述两页。

## 使用流程

1. **影像资料**：导入一部剧目的剧照目录及结果目录。填写服务端可访问的路径，读取该目录下的 JPG、JPEG、PNG、BMP、TIFF，不递归子目录。浏览缩略图、查看大图，按文件名、文件名中的演员/角色、候选幕次搜索，按待复核/已确认/已拒绝筛选。
2. **剧目与剧情**：填写 `剧目信息.txt` 和剧目资料目录，建立知识库；也可以在“知识库位置”中指定已有知识库并载入。界面展示已抽取的幕次与角色。纯 URL 文件需要先补充本地剧情正文或已有幕次标注，工作台不会自动抓取网页。
3. **演员与角色**：未标注剧照可扫描人脸分组，逐组命名入库；已有“演员饰角色”文件名可先检查，再建库。也可指定演员生成专辑。人脸模型必须已成功初始化。
4. **分析场景**：使用文件名与剧情线索，按需开启图文匹配和视觉模型辅助。视觉模型观察实际画面，再结合剧情生成候选；完成后自动进入复核队列，机器结果不会自动确认。
5. **场景复核**：选中剧照，在右侧查看原图、候选幕次、证据分以及可展开的剧情和画面依据；证据分不是正确概率。接受当前标签、选择其他幕次或填写修订，支持备注和拒绝。待复核筛选下保存后自动切换下一张。可用上一张/下一张按钮；焦点不在表单和按钮内时，左右方向键也能切换。
6. **整理与导出**：导出已确认标签，或直接执行整理。执行前自动重新导出最新人工标签，传入 `scene_evidence_file`，生成规范命名目录及报告。未审核、未知与已拒绝场景保持编号占位。结果可下载，并可切换到归档目录浏览。

项目路径、知识库位置、复核目录及模型开关保存在当前浏览器。刷新后重新读取服务器上的照片、知识库和复核结果。后台扫描状态仍沿用现有服务的进程内任务记录；刷新页面不会恢复扫描进度。长时间整理期间请保留页面，避免重复发起任务。

## 界面与接口

| 位置 | 职责 |
| --- | --- |
| `app/templates/workspace.html` | 页面结构、五个工作视图与项目设置 |
| `app/static/workspace.css` | 桌面侧栏、照片网格、移动底栏与响应式布局 |
| `app/static/workspace.js` | 项目上下文、API 串联、搜索筛选、分页、复核与结果展示 |
| `app/workspace_api.py` | 无模型依赖的图片枚举、按 EXIF 方向生成缩略图、报告下载 |
| `app/server_ui.py` | 页面与静态资源路由，保留旧版工具 |

新增只读接口：

| 方法 | 路径 | 参数 |
| --- | --- | --- |
| GET | `/api/workspace/photos` | `input_dir`，可选 `limit`（默认及最大 10000） |
| GET | `/api/workspace/thumbnail` | `input_dir`、`name`、可选 `size`（160–1920） |
| GET | `/api/workspace/artifact` | `output_dir`、`name`，仅 `scene_labels.json`、`organize_report.json`、`actor_view_report.json` |

缩略图与报告接口检查解析后的真实路径，拒绝跨目录和符号链接越界。超过 10000 张会明确提示分批整理。一个复核目录应对应一个照片目录，混入其他目录记录时工作台阻止导出。API 延续现有本地工具的访问权限模型，不新增身份认证。

`scene/reason` 及对话智能体包装改为传递绝对图片路径，修复图文检索因只拿到文件名而无法读取图片的问题。证据新增 `retrieval_mode`，候选补充 `scene_id`，知识库查询补充 `scene_options`，保持已有字段兼容。旧版裸文件名的人工复核结果在重跑时仍保留。
