# 幕间 · 多模态戏剧影像整理工作台

入口：启动 `python app/server_ui.py`，访问 `http://localhost:8199/organize`。`/ui` 同样打开工作台，`/` 重定向到工作台。

之前的可视化界面完整保留：工作台右上角「旧版界面」（桌面及手机均可见）或 `/legacy` 打开旧版照片处理页 `/legacy/ui`；原有智能整理表单位于 `/legacy/organize`。两页可通过顶部导航切换，也可点击「返回新版工作台」。原工具入口 `/tools` 和 `/organize/advanced` 继续可用，分别对应上述两页。

## 使用流程

1. **影像资料**：导入一部剧目的剧照目录及结果目录。填写服务端可访问的路径，读取该目录下的 JPG、JPEG、PNG、BMP、TIFF，不递归子目录。浏览缩略图、查看大图，按文件名、文件名中的演员/角色、候选幕次搜索，按待复核/已确认/已拒绝筛选。
2. **剧目与剧情**：填写 `剧目信息.txt` 和剧目资料目录，建立知识库；也可以在“知识库位置”中指定已有知识库并载入。界面展示已抽取的幕次与角色。纯 URL 文件需要先补充本地剧情正文或已有幕次标注，工作台不会自动抓取网页。
3. **演员与角色**：未标注剧照可扫描人脸分组，逐组命名入库；已有“演员饰角色”文件名可先检查，再建库。也可指定演员生成专辑。人脸模型必须已成功初始化。
4. **分析场景**：使用文件名与剧情线索，按需开启图文匹配和视觉模型辅助。视觉模型观察实际画面，再结合剧情生成候选；完成后自动进入复核队列，机器结果不会自动确认。
5. **场景复核**：选中剧照，在右侧查看原图、候选幕次、证据分以及可展开的剧情和画面依据；证据分不是正确概率。接受当前标签、选择其他幕次或填写修订，支持备注和拒绝。标签和备注自动保存为当前浏览器的草稿，切图、搜索、刷新或保存失败后保留；成功确认、修订或拒绝后清除。草稿不会自动写成服务器上的人工决定。待复核筛选下保存后自动切换下一张。可用上一张/下一张按钮；焦点不在表单和按钮内时，左右方向键也能切换。
6. **整理与导出**：导出已确认标签，或直接执行整理。执行前自动重新导出最新人工标签，传入 `scene_evidence_file`，生成规范命名目录及报告。未审核、未知与已拒绝场景保持编号占位。结果可下载，并可切换到归档目录浏览。

自动规范命名支持原始摄影文件名及带序号/日期/剧目的已整理文件名，复制到普通目录后仍可识别。再次整理保留日期、剧场和事项；旧幕次只作为分析线索，当前复核未批准时输出编号占位。不同整理序号不会据同名自动并为连拍。200图/4项目实际模型复验70项通过，原图与正式图库保留，范围见[升级进度](core_upgrade_progress.md)。

项目路径、知识库位置、复核目录、选中的照片及模型开关保存在当前浏览器。刷新后重新读取服务器上的照片、知识库和复核结果，并恢复该照片的草稿。保存复核决定后使用接口返回的单条记录更新状态和统计，不再重新下载全队列。若其他客户端先修改了同一记录，保存返回 409，自动载入该条最新结果并保留草稿；核对后再次保存。

复核初次加载读取用于搜索、筛选和状态统计的简要记录，完整剧情/画面依据随当前页和选中照片加载。翻页无需下载所有照片的证据；切换项目期间返回的旧请求不会覆盖当前项目。

2026-10-24起，工作台的单条决定直接持久写入SQLite及修订历史，导出时再更新兼容JSONL快照。重启和刷新读取最新决定；直接复制旧JSONL前应先导出。API的`defer_snapshot`默认关闭以兼容旧调用，工作台保存和冲突刷新显式启用；元数据、分页详情及场景证据读取使用SQLite。13项存储回归、27项API和五屏宽浏览器检查已通过，证据位于`outputs/acceptance/core_upgrade/completion_followup_20261023/`。

开启“视觉模型辅助”后，系统按候选不确定性和调用预算补充观察；并非每张图都会请求视觉模型。默认 100 图批次最多 30 次实际请求，一张完整补充分析包含观察和判断两次。按需 OCR、单图视觉策略及实验分段/图聚类通过任务 API 配置，格式与使用条件见[实验组件指南](experimental_components_guide.md)。默认仍使用 SigLIP2 与现有分段/聚类方法。

场景分析在后台运行，可继续看图复核；刷新会恢复同一任务，不重复提交。任务栏显示成功、失败和待处理数。“取消分析”等待当前图片结束后停止，“继续未完成图片”跳过已保存结果。服务中断后需要手动继续；失败图片可用“按当前资料重新分析”重试。任务保存创建时的知识快照与原图摘要，原图变化不会静默复用旧判断。整理、剧目知识库构建、演员扫描和标注照片人脸建库也使用持久后台任务，刷新可恢复状态，取消后可继续未完成项。

人脸建库的「仅统计」使用与实际建库相同的配额和多人匹配传播规则，不写图库。取消可能发生在部分锚定图已发布之后，继续会核对并复用本任务的相同文件；其他人改动图库或切换模型时须新建任务。完成后可下载建库报告，失败图片保留原图。图库与报告应放在照片目录之外，未完成任务同时占用这两个位置。

## 演员身份与剧目角色

“整理与导出”中的“演员与角色表”可填写已核对 JSON 的服务端路径，并随项目保存；整理和演员专辑都会使用它。留空读取人脸库内的 `identity_registry.json`。同一演员的多个锚定目录按身份 ID 合并，只用当前剧目的唯一已确认角色命名；没有角色表、剧目不明或一人多角时只写演员名。

演员专辑支持登记姓名、图库目录及精确身份 ID 筛选。登记的同名不同身份会使用稳定的 `[identity_id]` 区分，分别出现在不同照片时也不会合并为一个专辑。表的 JSON 示例、API 字段、阈值、逐脸报告和改表后的任务恢复规则见 [演员身份与剧目角色表指南](identity_registry_guide.md)。

新增只读接口：

| 方法 | 路径 | 参数 |
| --- | --- | --- |
| GET | `/api/workspace/photos` | `input_dir`，可选 `limit`（默认及最大 10000） |
| GET | `/api/workspace/thumbnail` | `input_dir`、`name`、可选 `size`（160–1920） |

缩略图与报告接口检查解析后的真实路径，拒绝跨目录和符号链接越界。超过 10000 张会明确提示分批整理。一个复核目录应对应一个照片目录，混入其他目录记录时工作台阻止导出。API 延续现有本地工具的访问权限模型，不新增身份认证。

缩略图按完整源文件内容、EXIF 处理规则、尺寸、JPEG 配置与 Pillow 版本缓存。命中后仍读取源文件校验内容，但无需解码原图；复制、改名可复用。同大小改写并恢复 mtime 会失效，生成期间改写返回 409。响应使用 ETag 与浏览器重新验证，未变化返回 304。缓存默认位于 `outputs/thumbnail_cache`，上限 256 MiB / 4096 项；可用 `TRANS_THUMBNAIL_CACHE_DIR`、`TRANS_THUMBNAIL_CACHE_MAX_BYTES`、`TRANS_THUMBNAIL_CACHE_MAX_ENTRIES` 配置。容量清理只删除该新目录下符合缓存命名的普通条目，跨进程发布由文件锁串行化；原图和其他目录不参与清理。

`scene/reason` 及对话智能体包装改为传递绝对图片路径，修复图文检索因只拿到文件名而无法读取图片的问题。证据新增 `retrieval_mode`，候选补充 `scene_id`，知识库查询补充 `scene_options`，保持已有字段兼容。旧版裸文件名的人工复核结果在重跑时仍保留。
