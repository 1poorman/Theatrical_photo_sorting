# Qdrant 在线向量库改造与容器对比（2026-11-02）

已将 Docker 默认图像、人脸后端切换为 Qdrant，完成增删、过滤、模型隔离、旧库迁移与重启验收。采用价值是在线维护和降低检索客户端对图库规模的内存依赖；小规模常驻 FAISS 仍明显更快。图像和人脸保持精确检索默认，HNSW 只作为显式选项。

10 万条合成向量上，Qdrant 精确查询 p50 为 **24.21 ms**，旧 FAISS 每次重载为 **752.95 ms**；客户端采样峰值 RSS 分别为 **46.48 / 649.32 MiB**。这是共享机器上的向量检索测量，不含模型与完整 HTTP 耗时，不是服务 SLA 或整体内存节省比例。

真实人脸向量查询中，当前 ES script_score p50 **5.78 ms**，Qdrant 精确为 **2.25 ms**，两者相对于 FAISS 的 recall@10 均为 100%。10 万合成向量的 HNSW recall@10 仅 **44.70%**，不足以替换默认精确查询。

## 实现与适用范围

- 图像向量按 32 张一批提取、上传，数据库保存向量、路径、内容哈希及项目/剧目/场景字段；最终真实 HTTP 测试的本地清单为 503 字节，无 `.faiss` / `.npy` 全量副本。路径列表仍占随图片数量增长的内存。
- 相同路径使用稳定 ID；写入与删除确认后可查询。全量重建成功才发布新清单，失败保留旧库；保留上一代并提供带所有者、年龄和锁检查的历史集合清理工具。增量多批操作不是跨批事务。
- 图像校验模型与预处理签名，人脸按 ArcFace 权重隔离；人脸余弦阈值和人物去重语义保持。模型推理使用锁，数据库写入期间允许其他查询提取特征。
- 旧 FAISS 仍可读取，ES 仍可启动迁移/回退；源照片、旧向量、图库与复核记录保留。Qdrant 查询直接由数据库执行，离线 FAISS 分组不受该切换影响。
- 选择 Qdrant 基于单容器部署、向量检索和元数据操作需求；没有进行 Milvus/pgvector 对比，不宣称跨产品全面领先。

实施前的 [方案](../../qdrant_upgrade_plan.md) 与 [操作/迁移/容量指南](../../qdrant_guide.md) 已记录接口和复现命令。

FAISS 每次重载包含 `.faiss`、`.npy` 及路径列表读取，与旧加载方式对应；常驻 FAISS 是可优化的参照，仅保留检索索引。Qdrant 使用 REST+JSON，ES 使用现有 Python 客户端。特征提取不计入检索时间，常驻索引的一次加载也不计入其首查。基准 Qdrant payload 为序号、图片路径和项目字段，ES 为向量和序号；完整业务还包含内容哈希、人物等元数据，其存储和响应大小需要另计。

客户端 RSS 从 `/proc/self/status` 每 2 ms 采样，包含导入基线，可能漏掉更短的尖峰；这些是纯向量 worker，不是含 GPU 模型的整个应用。服务器资源另列。首查没有清操作系统缓存，不能称为冷盘读取。查询耗时和顺序 QPS 不能推导高并发吞吐。

HNSW m=16、ef_construct=100、查询 ef=128。生产 full_scan_threshold=10000 KB、indexing_threshold=1000 KB；基准合成集合将两个阈值都设为 1000 KB，等待 green 且至少 95% 向量已索引后测量，以避免小段触发全扫描。真实小集合没有建立 HNSW，表中 `exact=false` 实际仍是扫描。最终各集合完整配置保存在 [comparison.json](comparison.json)。未索引尾部仍可能精确扫描。

旧 FAISS 文件统计 `.faiss`、`.npy` 两份向量与路径文本；Qdrant 按每个集合统计，包含段、payload、索引和 WAL。表观大小是文件 st_size 之和，实际分配是 st_blocks×512；两者差异来自稀疏/预分配文件。表观数值不等于已经占用的磁盘块，备份方式也可能改变稀疏文件占用。小集合有固定开销，大集合不能只用原始向量字节数估算总空间。

写入列是初始实验的已提取向量写盘/上传时间，Qdrant 上传含网络和持久化确认，不包含最终 HNSW 全部构建完成。初始 indexing_threshold=10000 KB，10,000 条集合等待达到 300 秒上限时还未建立索引；之后校正为 1000 KB 并重测查询。初始写入时间并非最终配置的完整建库速度，不据此作吞吐优劣结论。

最终资源快照中，Qdrant 进程 RSS **1228.62 MiB**，容器 memory.current **953.33 MiB**，其中 file **719.21 MiB**、anon **181.60 MiB**。该服务同时保留四个基准集合和验收集合，不是任何单一数据规模的独占内存，也不是运行全程峰值。[资源快照](qdrant_resources.json) 与 [三容器 docker stats](container_resources.txt) 保留不同统计口径；`docker stats` 扣除部分缓存，不能直接与进程 RSS 等同。ES 还拥有 JVM/段缓存，配置和业务规模与 Qdrant 不同，不能由这两个快照推出整体内存倍数。

数据库仍使用磁盘；默认 Qdrant 卷位于同一宿主机，磁盘耗尽问题不会凭入库消失。可独立部署数据库并配置容量、备份与历史集合清理。768 维 float32 每百万条原始向量约 2.86 GiB，旧双份文件约 5.72 GiB；数据库索引、payload、WAL、重建临时副本和原图需另留空间。
